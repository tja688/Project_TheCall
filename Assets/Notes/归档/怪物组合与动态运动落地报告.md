# 怪物组合与动态运动落地报告

## 目标与结论

游戏需要用少量手绘图形成稳定、可读、可遗传且可轻微运动的怪物。旧实现把怪物 ID 哈希值分别偏移后用于身体、头、眼、嘴等九个独立选图；随机组合没有语义约束，任何来源的头部与脸部细节都可能交叉搭配。预制体虽然各层都设为铺满 142x102，但 Image 允许非等比拉伸，没有显式的头、脚运动枢轴；运行时画像颜色也一律为白色。

新实现把怪物外观建模为稳定的兼容配方索引和调色板索引。运行时由 `Monster` 持有，查询投影传到每一个画像。六个兼容配方固定整套身体、头部、眼、嘴、手、脚组合，可选头饰、尾巴和胸饰；主色只染身体、头、脚，脸部黑色轮廓与表情维持原样。双亲本时子代取第一位亲本配方、第二位亲本颜色；只有一位亲本时取同一只的两项。现有 `IDraw` 抽取序列不增加调用，因此技能遗传的随机规则保持原样。

操作区直接拖拽生成的 ghost 使用受限、阻尼的角弹簧：横向指针速度驱动头部与脚反向摆动，最大约 7 度和 5 度。它只运行于一个拖拽副本，无常驻列表动画、刚体或碰撞计算；松手后副本销毁，原物件仍是静止姿态。

## 源素材审查

- 美术组合参考：`Assets/示意图/怪物拼接示意图.jpg`，画布 142x102。
- 原始分层稿：`Assets/Arts/Others/怪物部位`；运行时资源：`Assets/Resources/MonsterParts`。
- 九类资源：身体 6、头 4、眼 5、嘴 6、手 5、脚 3、尾巴 3、头饰 4、配饰 3。
- 所有部件保持统一的完整透明画布。导入为 Sprite、Full Rect、中心 pivot、100 PPU、Point 过滤、不启用 mipmap、未压缩，因而同尺寸 RectTransform 能维持像素位置一致。
- 需要持续维护源稿与 Resources 运行时副本的一致性；增加身体、头、眼或嘴素材时，要先确认其插画语义与六套兼容配方对应关系。

## 落地内容

- `Assets/Scripts/Core/Rules/MonsterAppearance.cs`：新增不可变外观值类型，索引构造时归一化。
- `Assets/Scripts/Core/Rules/RunModel.cs`、`MonsterView.cs`：外观归怪物自身持有、随视图读取；普通怪物创建基于稳定 ID 哈希产生可重复外观，繁殖可显式传入父代组合。
- `Assets/Scripts/Core/Rules/BreedingSystem.cs`：父代配方和颜色分别遗传，不改变已有技能抽取或变异规则。
- `Assets/Scripts/Core/Rules/ShelfQuery.cs`、`ShopSystem.cs`、`MonsterDetails.cs`、`MonsterDetailsQuery.cs`：商店货架、怪物详情查询完整带出外观。
- `Assets/Scripts/Presentation/Hover/MonsterPortrait.cs`：一个小接口负责配方选择、调色、部件启用、资源缓存和姿势复位。
- `Assets/Scripts/Presentation/OperationPointer.cs`：只为当前拖动 ghost 计算弹簧响应。
- `Assets/Editor/PresentationSceneBuilder.cs`：重建预制体时建立 HeadMotion 与 FeetMotion 组，将五官与头绑定到同一运动组，并把运动组放置在现有身体层级上方。
- `Assets/Notes/表现层Demo交接.md`：加入资产、枢轴、配色、遗传和运动维护约定。

## 组合约束

身体、头和脸部各自画在相同画布，不代表每一组 ID 的结构语义天然匹配。当前运行时明确按同一个 `recipe` 索引查头、身体、眼、嘴、手和脚，避免不同表情系统错配。配饰是有条件显示的，避免九层同时叠满。这里的六套关系是当前素材集上的配置，不是自动识别审美的算法；新增或重画素材必须由美术在图上确认后更新映射。

着色依赖部件素材的透明与像素配色。如果一层使用多种固有颜色，简单 `Image.color` 会整体乘色，不适合作为该层的语义色控制；应把图拆为轮廓与可染色填充层或单独增加填充 mask，而不是把轮廓着色当成理所当然。

## 验证计划与限制

- 使用 Unity 6.6.0f1 项目内的现有 Editor，通过 Unity CLI 重建 `MonsterPortrait.prefab` 与 `Main.unity`；不手改场景 YAML。
- 在 Play Mode 验证主菜单画面中首轮怪物渲染、颜色和分层，并检查 Unity Console 编译错误。
- 运行核心繁殖测试及现有编辑器测试；重点确认技能规则未被改变。
- 验证拖动时仅 ghost 的 HeadMotion、FeetMotion 出现角度变化，并验证松手销毁 ghost 后静态画像恢复原角度。
- UI 弹簧不属于 Rigidbody2D/3D 物理模拟，没有质量、碰撞、碰撞体或接触约束。若以后需要身体之间相互碰撞或摆动尾巴，应独立选用适合 UI Canvas 的自定义约束或改用世界空间骨骼方案。
- 构建命令会重建 `Main.unity` 的 `UICanvas` 和画像预制体。已有场景内这些对象的人工改动可能被覆盖；本次用户已明确允许自行尝试，且通过项目 Editor 菜单执行。
