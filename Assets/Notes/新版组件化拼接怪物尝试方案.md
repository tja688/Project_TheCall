我建议你们采用：**少量体型模板＋明确的连接挂点＋带兼容规则的随机组合＋程序驱动的轻量动画。**

这套方案的核心，是让美术定义好“部件怎样连接、哪些组合成立”，然后让程序在这个范围内创造变化。工作量主要随**部件数量和体型数量**增加，不需要随最终怪物组合数增加。

从图 2 看，你们的美术方向已经成立了。它们可以很怪、很不对称，但头脸关系、身体比例和四肢位置仍然清楚。接下来要做的是把这些人工选择，变成程序能遵守的规则。

下面用简化图形演示这套结构：可以切换体型、头型和表情，拖动怪物观察回弹，也可以打开挂点。

**现有方案可以保留素材，但需要改变“整张画布叠起来”的组织方式。**

统一使用 142×102 透明画布，本身没有问题。如果所有部件都是围绕同一个体型设计的，这种方式甚至很省事。但它只能保存部件原来的像素位置，不能自动适应不同头型、身体和姿态。

你们当前机制有几个明确的限制：

| 当前做法             | 对效果的影响               | 建议改变           |
| ---------------- | -------------------- | -------------- |
| 所有层放在同一个矩形中      | 不同部件沿用原来的位置，无法适应当前身体 | 用身体挂点决定安装位置    |
| 所有头使用相同五官位置      | 五官可能碰到脑组织、补丁或头部边缘    | 每个头型配置自己的脸部布局  |
| 一个配方索引通过取余选择多个部件 | 部件被索引偶然绑定，难以表达真正的遗传  | 分别保存各部件的稳定 ID  |
| 所有层采用同一套前后顺序     | 某些根部接缝露出，某些装饰压住五官    | 由体型和部件指定遮挡关系   |
| 每层都是完整画布         | 直接旋转时，容易绕画布中心摆动      | 绕脖子、腿根、翼根等位置旋转 |

图 3 中能看到面部区域的轮廓挤在一起，但仅凭截图不能断定具体是哪项导入设置或选图映射出了错。**需要先检查实际选中了哪些图，再解决结构规则；改变渲染顺序本身无法修好五官位置。**

---

**最值得投入的，是“身体决定连接位置，头型决定五官布局”。**

建议首版先支持两类姿态：

* **直立型**：头在上方，身体居中，脚在下方。
* **横卧型**：身体横向展开，头偏前，脚沿身体下缘分布。

每类姿态可以有多个身体轮廓。它们共用组织方式，但各自保存挂点坐标。图中头身几乎融合的类型，可以先作为一种整体基础部件，避免强行再叠一个独立身体。

这里的“模板”不等于固定套装。它只规定结构，例如脖子在哪里、背上能不能装翅膀、脚从哪里伸出来。头、表情、尾巴和颜色仍然可以变化。

建议把素材配置分成下面几类：

| 配置对象  | 至少需要保存的内容                      |
| ----- | ------------------------------ |
| 身体    | 体型类别、头／手／脚／翅膀／尾巴挂点、站立基线、默认遮挡顺序 |
| 头     | 脖子连接点、五官挂点、允许的眼数、五官可用区域、头饰位置   |
| 四肢与尾巴 | 根部连接点、适用接口、默认角度、尺寸范围、最大摆动角度    |
| 装饰    | 安装位置、显示在主体前还是后、颜色类别、是否占用某个区域   |

例如，你们的脑组织头型，上方和一侧已经有很强的结构，五官就应当安排在剩余区域；补丁头可以支持单眼布局；糖果头可以支持较对称的双眼布局。

**这些通常只是坐标和规则配置，不需要为每一种组合重新画图。**

首版我还建议把眼和嘴组织成几套经过选择的表情组合，例如困倦、兴奋、呆滞。每个头型分别校准这些组合的位置。现有眼睛和嘴巴素材可以继续使用，只是减少首版完全独立随机造成的冲突。后续再逐步开放眼嘴自由组合。

---

**挂点解决位置，接缝还需要少量美术规范。**

一个部件即使安装位置正确，连接宽度不对、根部黑线过重，也会显得像贴上去的。

你们可以采用很适合这种手绘风格的“纸偶”处理：

1. **根部伸入主体。** 手、脚、尾巴和翅膀的根部留一小段隐藏区域。
2. **主体遮住根部。** 后置肢体先画，身体后画，接头自然藏在身体下方。
3. **隐藏段减少轮廓线。** 避免肩膀、腿根出现两圈叠在一起的黑线。
4. **需要时用缝线或小领圈遮接头。** 你们已有补丁、缝合的视觉语言，很适合把连接处设计成风格的一部分。

以最终显示尺寸接近 142×102 为例，隐藏重叠可以先尝试几像素，再检查最大摆动时会不会露缝。这是调试起点，具体需要看你们的线宽和零件尺寸。

另外，需要统一的是**连接接口、视角和笔触尺度**，不一定是所有图片的尺寸。建议定义少量接口规格，例如“小脖子”“标准翼根”，并限制局部缩放范围。不要依靠大幅缩放把所有东西硬接上去，线宽和比例会跟着失衡。

现有透明画布可以继续保留。先补挂点和层级，之后再考虑裁掉透明边缘；裁切不是修好拼接的必要前提。

---

**遗传应当先锁定特征，再寻找能承载这些特征的身体。**

你们描述的“父亲的小翅膀＋母亲的脚＋随机身体”，完全可以保留。关键是随机选择的先后顺序。

建议生成流程如下：

1. **决定必须继承的外观特征。** 例如父亲的翅膀和母亲的脚。
2. **筛选能够安装这些特征的身体。** 身体仍然可以来自随机池，但候选池经过兼容筛选。
3. **选择适合该身体接口的头。**
4. **根据头型选择脸部布局，再选择表情。**
5. **选择尾巴、头饰等可选件和配色。**
6. **检查尺寸、遮挡和装饰数量，再固定结果。**

例如，一个身体没有翼根挂点，它就不应进入“必须继承翅膀”的候选池。

如果你们承诺某个继承特征必定能看见，就应把它作为硬约束。还需要准备一个能承载本期允许继承接口的通用体型作为保底。做不到通用承载时，就要明确限制哪些特征能同时显性出现，或者给少数特征准备适配变体。程序不应悄悄删掉玩家期待继承的部件。

兼容规则也不要发展成“每两个部件都写一条规则”。优先使用少量类别：

* 接口类别是否一致。
* 体型是否支持该部件。
* 尺寸是否在允许范围内。
* 是否占用五官或其他装饰的区域。

只有少数特殊素材使用例外规则。这样新增一个部件时，只需要标记它支持哪些接口。

**这会限制一些组合，但保留了你们真正需要的随机性：孩子能看出父母特征，也能出现意外的新轮廓。**

---

**多样性优先来自轮廓和性格，颜色和装饰负责补充。**

对于这样的小尺寸怪物，我建议把投入顺序放在：

**身体轮廓 → 头型 → 表情 → 配色 → 小装饰。**

大轮廓的差异，通常比多增加一个小配饰更容易被玩家辨认。图 2 中，直立长脚、横卧身体、巨大头部这些变化，本身就已经很有效。

举一个规模示例：

> 4 个头 × 6 个身体 × 3 套表情 × 3 套脚 × 4 种尾巴状态 × 6 套配色
> = 5,184 种原始组合。

这是未扣除兼容规则的组合上限，也不代表玩家能感受到 5,184 个独特形象。但它说明：**不必画几千只怪物，也可以得到足够丰富的结果。** 手、翅膀和头饰还可以继续扩展这个空间。

可选部件应该允许为空。普通怪物可以没有尾巴或头饰，避免每只怪物都塞满零件。稀有怪物更适合拥有一个醒目的特征，例如特殊翼形、长角或花纹，让它在缩略图里也能被认出来。

技能关联可以影响候选权重，例如某个技能族更容易出现对应翼形或装饰。若外观和技能只是弱关联，就需要在详情中明确显示技能，避免玩家把“有翅膀”理解成必定拥有某项能力。

**配色也建议使用经过美术选择的色板。** 每套色板包含主色、辅色和固定细节色：

* 身体、头，以及同材质的手脚、尾巴使用主色。
* 翼膜、耳内或少量装饰使用辅色。
* 牙齿、眼白、舌头等保留固定颜色。

你们目前只给身体、头和脚乘色，可能会让手、尾巴与身体脱节。应按材质类别分配颜色。

如果一张图里同时有需要变色的皮肤和需要保持原色的细节，首版可以仅对这些复杂部件拆成“可变色底图＋固定细节层”。不需要让每个部件都增加一套遮罩。

---

**Unity 中，建议沿用现有显示体系，先改数据和层级。**

你们当前看起来主要使用 UGUI `Image` 显示怪物。一个月周期内，可以继续使用 `RectTransform + Image`，不用为了这套需求迁移整个展示体系。

但每个部件需要有自己的位置和旋转支点。`preserveAspect` 负责保持图片宽高比，旋转中心则由 `RectTransform.pivot` 决定；它们不会自动识别部件的连接位置。([docs.unity3d.com][1])

建议明确区分：

* **挂点**：身体上的安装位置，例如脖子在哪里。
* **支点**：部件自身绕哪里转，例如头底部的脖子连接处。

安装时把两者对齐。五官、头饰跟随头的运动层；身体装饰跟随身体；脚有自己的腿根运动层。

UGUI 中还要显式设置 `RectTransform` 的 pivot，不要只修改 Sprite 的 pivot。若以后改用 `SpriteRenderer`，则可以使用 Sprite 的自定义 pivot。归一化坐标需要统一方向，尤其注意绘图软件常用左上原点，而 Unity 的相关 Sprite 坐标采用左下原点。([docs.unity3d.com][2])

前后显示顺序与连接层级要分别管理。UGUI 通过层级顺序组织；如果使用多个 `SpriteRenderer` 拼角色，可以在怪物根节点使用 `SortingGroup`，避免不同怪物的零件互相穿插。**它解决的是怪物之间的排序，五官和接缝仍需自己的规则。**([docs.unity3d.com][3])

数据建议分为三层：

| 数据     | 职责                              |
| ------ | ------------------------------- |
| 部件配置   | 保存 Sprite、稳定 ID、接口、挂点、颜色类别和运动参数 |
| 怪物外观数据 | 保存这只怪物实际选中的身体、头、表情、四肢、装饰和色板 ID  |
| 显示组件   | 读取外观数据，完成拼装和动画                  |

可以使用 `ScriptableObject` 管理配置。存档保存稳定 ID，不要依赖文件名排序后的数组下标：新增或改名一个文件，可能改变后续下标。

也不要只保存随机种子。部件池和生成算法更新后，同一个种子可能生成不同外观。应保存**已经确定的部件选择**，种子只负责待机相位等细微差异。

你们让收容笼、操作区、商店和详情读取同一份外观数据，这一点值得保留。旧六套配方可以一次性映射成明确的部件 ID，继续保住已有怪物的样子。

Unity 的 Sprite Library / Sprite Resolver 可以辅助管理换图，但不会替你们解决接口和兼容性。如果以后采用骨骼换图，Unity 官方要求被交换的 Sprite 使用相同骨骼；首版这套轻量 Transform 动画可以先直接替换 Sprite。([docs.unity3d.com][4])

**拖动动画，用“有限角度目标＋阻尼弹簧”就能达到你们需要的质感。**

首先让怪物根节点响应拖动，再根据实际移动速度，给头、脚、尾巴不同的倾斜目标：

```text
移动速度 = 当前根节点位置与上一帧位置之差 / 时间
头部目标角度 = 限制后的“反向移动速度 × 响应系数”
脚部目标角度 = 限制后的“移动速度 × 响应系数”

各部件通过阻尼弹簧追随目标角度
停止移动后，目标回到零，部件继续轻微回弹
```

这是带惯性质感的表现动画。头、脚不需要各自挂 `Rigidbody2D` 和关节。

弹簧可以按下面的关系实现：

$$
\ddot{\theta}
=\omega^2(\theta_{\text{目标}}-\theta)
-2\zeta\omega\dot{\theta}
$$

程序实现时使用稳定的弹簧更新方法。需要少量回弹，可以将阻尼比先放在约 `0.65–0.85`，再根据实际效果调节。

以下参数可作为试做起点，不能直接当作所有素材的统一标准：

| 部位    |    拖动时的局部摆角 | 待机表现            |
| ----- | ----------: | --------------- |
| 头     |    约 ±6–10° | 约 ±1–2°，或轻微上下移动 |
| 脚     |     约 ±4–8° | 站立时基本固定         |
| 尾巴、软翼 |    约 ±8–14° | 幅度更小、节奏略慢       |
| 身体    | 整体倾斜约 ±2–4° | 高度变化约 2–3%      |

**五官必须跟着头整体运动。** 不要让头、眼睛、嘴分别摇摆，否则会再次出现部件混在一起的感觉。

另外几个实现细节很影响最终效果：

* 使用同一坐标空间测量移动速度，避免 Canvas 缩放改变摆动强度。UGUI 可以先将屏幕坐标转换为父节点本地坐标。([Scripting API: RectTransformUtility][5])
* 过滤并限制速度。生成、换父节点或瞬间传送时，重置位置采样，避免突然甩飞。
* 动画始终从保存的静止姿态计算，不要持续累加旋转和位置。
* 最大摆角需要结合接缝检查；隐藏根部短的部件，就使用更小的角度。
* 放下时保留一点回弹，再用约 0.2 秒逐渐进入待机。

**呼吸主要动上身，脚保持落地。**

可以让身体轻微拉伸，头的挂点随上身缓慢上移，尾巴有一点不同相位的摆动。呼吸周期先尝试 2–3 秒，每只怪物的相位由固定种子决定，避免整个笼子里的怪物同时起伏。

不要直接缩放包含全部四肢的根节点，否则脚也会跟着伸缩，容易产生漂浮感。身体图形的缩放、上身挂点的移动和脚的位置，应分别控制。

---

**验收时重点看：**

* 在最小显示尺寸下，脸和轮廓是否仍清楚。
* 最大头配最小身体、最长脚配最短身体，是否仍成立。
* 最大摆角下，接缝是否露出，嘴和装饰是否碰撞。
* 深色游戏背景下，各套配色是否保持可读。
* 各个界面是否显示同一只怪物。
* 无合法候选时，保底规则是否仍符合遗传承诺。
